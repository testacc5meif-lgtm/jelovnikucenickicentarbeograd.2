# Јеловник — Ученички центар Београд

PWA која сама преузима јеловник са сајта установе, чита га, уписује у базу и
шаље обавештења пред сваки оброк. Апликација се отвара тренутно, јер је
обрада PDF-а већ обављена у позадини.

## Шта треба знати о извору

Проверено на јеловнику за 1–15. септембар 2026:

- PDF је **скениран**, четири стране, свака уграђена JPEG слика. Нема текстуалног
  слоја, па класична екстракција враћа нула бајтова. Обраду ради Tesseract,
  бесплатно и на самој машини, без иједног плаћеног сервиса.
- Извор је **већ на ћирилици**. Пресловљавање латинице остаје као заштитна мрежа
  у `src/translit.js`, али није главни ток.
- У колони оброка **нова ставка почиње цртицом на почетку реда**. Ред без цртице
  је наставак претходне ставке због прелома текста. Зарези унутар ставке се не
  деле, па `печена пилетина, динстани пиринач, парадајз сос` остаје једна ставка.
- На страници стоји **само један PDF у датом тренутку**, без архиве. Историју
  чува ова апликација.

## Покретање

```bash
npm install
cp .env.example .env
npm run vapid          # упиши добијене кључеве у .env
npm run tessdata       # скида српске језичке податке за Tesseract
npm run ingest         # преузми и обради актуелни јеловник
npm start
```

Tesseract мора да буде инсталиран. На Debian и Ubuntu:

```bash
apt-get install -y tesseract-ocr poppler-utils
```

`poppler-utils` доноси `pdftoppm`, који исправно исцртава сваку страну PDF-а.
Без њега систем вади уграђене слике из фајла, што ради за скениране
документе какав овај јеловник јесте, али не и за све PDF-ове.

Апликација ради на `http://localhost:3000`.

Обавезно у `.env`:

| Променљива | Чему служи |
| --- | --- |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Web Push |
| `PUBLIC_URL` | адреса која се отвара кликом на обавештење |
| `TESSERACT_BIN` | путања до Tesseract-а, ако није на PATH-у |

## Команде

| Команда | Шта ради |
| --- | --- |
| `npm start` | сервер, распоред послова и слање обавештења |
| `npm run ingest` | једнократно провери сајт и обради нове PDF-ове |
| `npm run seed` | упиши демо јеловник из `fixtures/` |
| `npm run tessdata` | скини српске језичке податке за Tesseract |
| `npm run verify` | измери тачност обраде у односу на еталон |
| `npm test` | тестови пресловљавања, нормализације и текстова обавештења |
| `npm run notify:test rucak` | одмах пошаљи најаву, за проверу |
| `npm run pg` | подигни локални Postgres за развој, без инсталације |

`node scripts/ingest-once.js --file lokalni.pdf` обрађује локални PDF.

## Како ради

```
сајт ──► scraper.js ──► pdf-pages.js ──► ocr.js ──► table.js ──► dictionary.js
 (сваког сата)  нови PDF?   слике страна   Tesseract  табела из     исправка
                                                      координата    грешака
                                                                       │
                                    PWA ◄── API ◄── SQLite ◄───────────┘
                                     ▲
                 scheduler.js ──► push.js ──► Web Push
                 22:30 / 10:30 / 17:30
```

- **`src/scraper.js`** чита страницу, налази PDF линкове и рачуна SHA-256 отисак.
  Већ обрађен фајл се препознаје по отиску и прескаче, па поновно покретање
  ништа не кошта.
- **`src/pdf-pages.js`** претвара PDF у слике страна, преко `pdftoppm` ако
  постоји, иначе вађењем уграђених слика из фајла.
- **`src/ocr.js`** пушта сваку страну кроз Tesseract и враћа речи са
  координатама и поузданошћу читања.
- **`src/table.js`** реконструише табелу геометријски. Заглавља ДОРУЧАК,
  РУЧАК и ВЕЧЕРА дају границе колона, цртица на почетку реда отвара нову
  ставку, а датум се чита само из цифара јер се дан у недељи израчунава.
- **`src/dictionary.js`** исправља оно што је скен поквaрио, поређењем са
  већ виђеним јелима.
- **`src/extract.js`** спаја те кораке и означава дане који изгледају
  необично, да се погрешан јеловник не прикаже као тачан.
- **`src/db.js`** бира складиште и износи исти, увек асинхрони облик, па
  остатак система не зна коју базу користи. `src/store/sqlite.js` ради на
  уграђеном `node:sqlite`, `src/store/postgres.js` на Postgres-у.
- **`src/scheduler.js`** cron послови у зони `Europe/Belgrade`.
- **`src/push.js`** слање, уз брисање претплата на које прегледач врати 404 или 410.

## Обавештења

| Време | Најављује | Оброк почиње |
| --- | --- | --- |
| 22:30 | сутрашњи доручак | 06:00 |
| 10:30 | данашњи ручак | 11:30 |
| 17:30 | данашњу вечеру | 18:30 |

Текстови су у `src/messages.js`, седам по оброку, и бирају се по датуму тако да
се кроз недељу не понављају. **Ниједан не открива мени** — то штити тест
„ниједно обавештење не открива садржај менија”, који пореди сваку реч поруке са
свим јелима из еталона. Ако додаш нови текст који помиње јело, тест пада.

Ако мени за тражени дан не постоји, најава се не шаље. Дневник `sent_log`
спречава двоструко слање.

### Распоред без сталног процеса

На серверу који стално ради, распоред живи у самом процесу и ништа се не
подешава. На бесплатном хостингу који услугу успављује између захтева то
не важи, јер успаван процес нема ко да пробуди у 22:30.

За тај случај постоје руте под `/api/cron`, које споља позива бесплатан
сервис за распоред, на пример cron-job.org. Укључују се са:

```
SCHEDULER=off
CRON_SECRET=<дуга насумична тајна>
```

Док је `CRON_SECRET` празан, те руте не постоје. Тајна се шаље заглављем
`x-cron-secret`, никад у адреси, да не заврши у дневницима посредника.
Поређење је отпорно на мерење времена.

Шта тачно треба подесити говори сама апликација:

```bash
curl -H "x-cron-secret: $CRON_SECRET" https://tvoj-domen/api/cron/plan
```

Одговор даје cron изразе, путање и временску зону, па поставка не мора да
се преписује ручно из кода.

**Свака рута коју зове распоред враћа једанаест бајтова, `{"ok":true}`.**
То није ситница него услов да ствар ради: сервиси за распоред одбијају
одговоре преко неколико стотина бајтова уз поруку да је излаз превелик и
посао приказују као неуспешан, иако је уредно одрађен. Шта се стварно
десило види се у `/health`, не у одговору. Величину чува тест у
`test/responses.test.js`.

За посао који држи услугу будном постоји `/ping`, не `/health`. `/health`
носи дневнике и прелази килобајт, па за заказивање не ваља.

Буђења постоје зато што прво буђење успаване услуге траје до минут, а
сервиси за распоред прекидају везу после тридесетак секунди. Из истог
разлога руте за посао одговарају одмах, са ознаком 202, па тек онда раде
посао. Важно је да захтев пробуди процес, а исход стиже у дневник.

### iPhone

Web Push на iOS ради само када корисник дода апликацију на почетни екран
(Safari, дугме Подели, „Додај на почетни екран”). Апликација то препозна и у
прозору за обавештења покаже упутство уместо дугмета које не би радило. Ово је
ограничење система, не апликације, и једини начин да се заобиђе је native
апликација.

## Тачност обраде

`fixtures/jelovnik-2026-09-I.json` је ручно преписан јеловник за 1–15.09.2026,
свих 15 дана. Служи као еталон.

```bash
npm run verify
```

Мерење је поштено намерно. Речник за исправку у стварном раду долази из
ранијих јеловника, а не из оног који се управо обрађује, па команда за
речник узима само првих седам дана еталона и оцењује се на преосталих осам.
Опција `--holdout 0` искључује речник и даје сирову тачност.

Измерено на јеловнику за септембар 2026:

| Мера | Резултат |
| --- | --- |
| Скривених осам дана, речник од седам дана | 102 од 103, 99,0 одсто |
| Свих 15 дана | 192 од 194, 99,0 одсто |
| Без речника | 100 од 103, 97,1 одсто |

Преостале две грешке су по једно слово, `чсрба` уместо `чорба` и
`шаргерепа` уместо `шаргарепа`. Обе су чиста ћирилица, па их речник
намерно не дира: непотпун речник који „поправља" непознату ћириличну реч
чешће квари него што помаже, што је мерење и показало.

## Постављање на Render

Бесплатан план Render-а нема ни Tesseract ни poppler, па услуга иде као
контејнер. `Dockerfile` их доноси, а `render.yaml` описује поставку.

1. Направи Web Service из репозиторијума и изабери Docker.
2. Унеси променљиве које `render.yaml` означава са `sync: false`:
   `PUBLIC_URL` (домен који Render додели), `DATABASE_URL`, и три VAPID
   вредности. `CRON_SECRET` и `ADMIN_TOKEN` Render може сам да генерише.
3. `SCHEDULER=off` је већ подешен, јер се бесплатна услуга успављује.
4. Подеси спољни распоред по ономе што врати `/api/cron/plan`.

Слика скида језичке податке при градњи, а не при подизању, да прво
покретање не чека мрежу. Узима „best" издање, оно на коме је измерена
тачност од 99 одсто, јер је издање из Debian пакета друго.

## Постављање на сопствени сервер

Довољан је најмањи VPS. Потребан је Node 22.5 или новији због `node:sqlite`.

```
[Unit]
Description=Jelovnik
After=network.target

[Service]
WorkingDirectory=/opt/jelovnik
ExecStart=/usr/bin/node src/server.js
Restart=always
EnvironmentFile=/opt/jelovnik/.env
User=jelovnik

[Install]
WantedBy=multi-user.target
```

Испред иде обрнути посредник са HTTPS сертификатом, на пример Caddy:

```
jelovnik.primer.rs {
    reverse_proxy localhost:3000
}
```

HTTPS је обавезан. Без њега service worker се не региструје, па нема ни
инсталације на почетни екран ни обавештења.

Резервна копија је један фајл: `data/jelovnik.db`.

## База

Подразумевано ради SQLite, један фајл, без икакве поставке. Ако је
`DATABASE_URL` подешен, ради Postgres. Оба складишта имају исти облик, па
се остатак система не мења.

### Supabase

1. Направи пројекат. Кредитна картица није потребна.
2. У подешавањима пројекта узми низ за повезивање, онај са ознаком
   *pooler*, и упиши га као `DATABASE_URL`. Уз њега иде `DATABASE_SSL=true`.
3. Покрени апликацију. Таблице се праве саме при подизању. Ако желиш да их
   направиш унапред, шема стоји у `db/schema.sql`.

Две ствари вреди знати.

Уз сваку Supabase базу иде и јавни REST приступ преко анонимног кључа.
Таблице направљене из SQL-а подразумевано немају укључену заштиту редова,
што би значило да свако са тим кључем може да чита претплате корисника.
Апликација зато при подизању укључује заштиту на свим таблицама, без
иједног правила, чиме тај пут остаје затворен. Сама наставља да ради јер
се повезује као власник таблица.

Бесплатан Supabase пројекат се гаси после недељу дана без саобраћаја. Ово
га не погађа, јер провера извора дира базу сваког сата.

### Развој без Supabase налога

```bash
npm run pg
```

Подиже преносиви Postgres, без инсталације на систем, и исписује адресу
коју треба поставити као `DATABASE_URL`. Исти тај Postgres користе и
тестови у `test/postgres.test.js`, па се Postgres пут проверава и без
иједног налога. За проверу на самом Supabase-у:

```bash
DATABASE_URL=<адреса> node --test test/postgres.test.js
```

База мора да буде UTF8, јер је цео садржај на ћирилици. Апликација то
проверава при подизању и јавља разумљиву грешку ако није.

## Прелазак на native апликацију

Backend је писан тако да претплата и слање не зависе од прегледача. За native
апликацију мења се само `src/push.js`, тако да поред Web Push шаље и преко FCM
или APNs. Табела `subscriptions` већ носи по једну претплату по уређају, распоред
послова и текстови остају нетакнути.
